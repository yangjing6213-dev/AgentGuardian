# AgentGuardian 设计规范

状态：用户已确认的设计基线，尚未进入实现阶段  
版本：0.1  
日期：2026-08-01  
产品中文名：AI Agent 守护者  
产品英文名：AgentGuardian  
缩写：AG

## 1. 产品定位

AgentGuardian 是一个本地优先的 AI Agent 数据安全审计平台，首个目标用户是 Windows 个人用户和小团队。它发现本机 AI 资产及其数据风险，给出可解释的 100 分审计结果和修复方案，经用户确认后执行受控修复，并在修复完成后自动复审。

视频分析得到的首要问题是：用户主动创建的 AI 分享页可能被搜索引擎发现，分享内容可能包含病历、简历、工作资料、API 密钥、密码和钱包信息。删除分享页不能替代密钥撤销和密码轮换；“获得链接者可访问”也不等于“不会被搜索发现”。因此产品首版必须同时覆盖分享暴露、敏感数据、凭据、权限和修复验证，而不是只做客户端清单。

本产品不宣称“保证绝对安全”。它展示审计范围、当前发现、证据置信度、未覆盖项和已执行验证，以便用户作出知情确认。

## 2. 已确认的设计决策

| 决策 | 结论 |

| 数据边界 | 本地优先、可验证出口；原始聊天、完整凭据和完整分享链接默认不外发 |

| 交互闭环 | 范围预览 → 只读扫描 → 证据确认 → 修复预览 → 用户批准 → 限权执行 → 独立复审 |
| 评分表达 | 安全分数 / 100 + 审计覆盖率 + 证据置信度 + 限制项 |

## 3. 产品可信模型

安全审计工具本身是潜在攻击面。可信性依赖可验证机制，而不是一句隐私承诺：

1. **开放透明**：扫描、规则、评分、修复动作契约和报告格式可被检查，支持可复现构建。
2. **最小权限**：普通用户权限运行；修复时只为单个已批准动作临时提权。
3. **零原文出端**：完整聊天、完整密钥、完整 URL 和浏览器凭据默认留在本机；任何可选出口都显示数据清单并单独授权。
4. **供应链证明**：发布物提供签名、哈希、SBOM 和构建来源；规则包签名后才可启用。
5. **修复可控**：LLM 不得自由生成并执行高权限命令；动作来自签名、预定义、可回滚目录。
6. **独立复审**：不以“命令执行成功”作为完成依据，必须重新读取实际状态和证据。
7. **自我审计**：检查自身安装完整性、权限、配置、网络连接、更新来源、日志和外发记录。

本地证据库使用 Windows DPAPI 保护。首版只保存位置、规则 ID、指纹和脱敏摘要；完整原文如需查看，留在原文件或用户明确选择的位置，不复制到报告和云端。

## 4. 首版审计范围

### 4.1 资产来源

- Windows AI 桌面客户端和 Web 应用的本地痕迹。
- 浏览器扩展、浏览器历史、下载和导出目录中的 AI 相关资产。
- Coding Agent、CLI Agent、IDE 插件和本地模型 WebUI。
- MCP 服务、Skills、Plugins 的配置和安装来源。
- 聊天缓存、日志、配置、导出文件、备份和剪贴板残留。
- 分享 URL、可匿名访问信号和用户明确授权的分享状态验证。

产品使用可插拔适配器维护产品清单，不把单一厂商的页面结构写死在核心评分中。首周只实现少量已知 Windows 配置路径和用户选择目录，未覆盖项必须列入报告。

### 4.2 六个评分领域

| 领域 | 权重 | 典型检查 | Founder Alpha |
| --- | ---: | --- | --- |
| 公开分享与外部暴露 | 20 | 分享页、匿名访问、索引信号、导出、云盘同步、浏览器历史、下载和删除残留 | 核心范围，有限适配 |
| 敏感数据与隐私 | 20 | 身份、联系方式、健康、金融、生物识别、位置、未成年人、简历、合同、客户、代码和企业机密 | 核心范围 |
| 密钥与身份凭据 | 20 | API Key、OAuth Token、Cookie、密码、SSH/云凭据、数据库连接、钱包私钥和助记词 | 核心范围 |
| Agent、MCP 与工具权限 | 20 | Shell、文件、网络、浏览器、剪贴板、环境变量、通配目录、危险组合权限和不受信服务 | 静态检查 |
| 网络外发与数据留存 | 10 | 遥测、训练开关、同步、代理、外部域名、日志、崩溃转储、缓存和删除能力 | 配置与静态证据 |
| 来源、更新与供应链 | 10 | 安装来源、签名、版本、依赖、扩展/MCP 包、仿冒、固定版本、安装脚本和更新通道 | 基础检查 |

行业策略包按医疗、金融、法律、人力资源、教育、政务、电商、研发、销售客服和媒体内容分组。策略包包含数据类型、敏感词、典型风险、严重程度、证据脱敏方式和修复建议。

### 4.3 定制关键词与企业策略

规则模型支持：

- 精确词、词典、通配符、正则、邻近关系、熵值和校验算法。
- 中文分词、大小写、排除词、路径/数据源范围、命中阈值和严重程度。
- 白名单、例外到期时间、掩码方式、处置建议、版本、签名和回滚。
- 个人策略使用 DPAPI 本地加密；企业策略包由组织签名后分发。
- 关键词原文不进入网络请求、普通报告或智能体提示词；测试使用合成样本。

规则执行采用“发现 → 去重 → 脱敏 → 证据指纹 → 风险归因”的顺序。同一根因只扣分一次，防止同一密钥出现在多个文件时无限放大风险。

## 5. 评分模型

总分为 100 分：

```text
领域扣分 D_i = min(领域权重 W_i, 同领域不同根因的有效扣分总和)
安全分数 = max(0, 100 - Σ D_i)
```

默认严重程度扣分为：严重 12、高 7、中 3、低 1；具体规则可在领域权重内校准。分数不使用证据置信度做隐式减免，避免“证据不确定”把风险伪装成低风险；置信度单独显示，并分为已确认、待用户确认和未覆盖。

额外规则：

- 仍有效的公开 API Key、钱包凭据或高敏公开页存在时，分数最高为 39。
- Shell、文件写入和网络外发形成不受控组合时，分数最高为 59。
- 未扫描范围不计为安全；关键范围未授权时报告标记为“审计不完整”，而不是安全通过。
- 100 分只表示当前选择范围内未发现已知问题，不代表绝对安全。

## 6. 修复与复审

### 6.1 修复动作

修复动作由签名动作目录提供，不允许大模型临时生成高权限命令。每个动作包含：

- 适用条件和受影响资产。
- 用户可读的变更预览。
- 最小权限和临时提权范围。
- 备份、回滚点和失败处理。
- 执行后验证方法。
- 对用户数据不可逆的动作默认不自动执行。

首版可提供的安全动作包括：备份并隔离高风险 MCP 配置、收紧明显过宽的本地文件权限、删除用户明确选择的本地导出副本、打开对应平台的分享管理页面并引导撤销。密钥撤销和密码轮换默认提供供应商步骤和验证清单，不假装已经完成。

### 6.2 验证

复审器重新读取真实状态，验证分享状态、文件权限、配置权限和凭据指纹是否变化。删除分享页不等于凭据安全；报告必须把“分享撤销”“凭据撤销”“密码轮换”“缓存清理”分成独立任务。

## 7. 运行界面

首屏是实际审计概览，不是营销欢迎页。界面包含概览、AI 资产、风险发现、修复中心、审计报告、策略与关键词、透明度中心七个入口。

视觉规范：

- 大量留白、清楚的层级、系统字体和稳定的布局尺寸。
- 中性黑白灰为底；可信绿表示已验证，琥珀表示需处理，红色表示严重风险，蓝色仅作辅助信号。
- 图标采用简单线性体系，动效只表达扫描进度、状态变化和确认反馈。
- “本地模式、数据外发、当前权限、规则版本、构建签名”始终可见。
- 使用 Inter / Noto Sans SC 或等价开源字体，不复制苹果或其他公司的商标、图标和具体组件样式。

固定流程为：范围预览 → 只读扫描 → 证据确认 → 修复预览 → 用户批准 → 限权执行 → 独立复审。

## 9. 单人 + 多智能体协作

最多三个并行写入智能体和一个只读审查智能体：

- **主编排者**：你和主智能体，负责范围、共享契约、集成、验收、日报和主线。
- **端点内核智能体**：资产发现、扫描宿主、本地证据库和系统权限。
- **检测安全智能体**：密钥、隐私、关键词、MCP 静态权限、评分规则和合成语料。
- **产品界面智能体**：桌面 UI、报告、确认流程和修复预览。
- **独立审查智能体**：只读威胁审查、测试执行、失败复现和发布复核。

所有写入智能体使用独立 worktree 和 Draft PR，目录所有权互斥；共享对象 `Asset`、`Evidence`、`Finding`、`Score`、`RemediationPlan`、`VerificationResult` 由主编排者冻结和变更。智能体只能使用合成数据，不读取用户真实聊天、密钥、浏览器凭据和本机视频证据。

有效加速预期为 1.7 至 2.3 倍，而不是智能体数量的线性倍增。第 5 天争取功能冻结，第 6 至 7 天必须保留给集成、安全测试和发布复核。

## 10. 进度与同步机制

GitHub 使用 Milestone、Issue、Project 看板和 Draft PR：

- 状态：Backlog、Ready、Doing、Review、Blocked、Done。
- Issue 控制在 2 至 4 小时，包含目标、非目标、依赖、验收、测试证据和风险。
- 只有测试、独立审查、提交哈希和复现证据齐全才能进入 Done。
- 验证通过的原子提交及时推送；主分支不接受未经验证的代码。
- `.analysis`、视频、转写、浏览器历史、密钥和本机证据永不提交。

每天北京时间 09:00 发送工作日报，包含昨日完成及证据、今日计划、测试、提交、阻塞、风险和里程碑偏差；没有进展时明确写“无变化”及原因。每周一更新进度基线。阶段完成报告包含目标、验收门、演示证据、未完成项、安全债务、指标和 Go/No-Go 决策。

## 11. 三阶段路线

### 阶段 1：可信本地审计

Founder Alpha 后用 5 至 7 周硬化为可邀请试用的 Windows MVP：增加适配器覆盖、误报基线、签名构建、安装升级、稳定性、回滚和真实用户验证。

### 阶段 2：持续防护

增加浏览器分享资产、暴露状态变化监控、受控匿名验证、MCP/Agent 运行时行为、签名规则更新、行业策略包和 macOS 技术预览。动态能力必须在沙箱中进行。

### 阶段 3：企业治理

增加设备注册、策略控制平面、组织/RBAC/SSO、集中报告、不可抵赖审计、行业合规映射、私有部署、租户隔离、灾备、第三方评估和企业试点。

## 12. 品牌规范

品牌采用 **Trust Frame**：四个开放角形成边界，`AG` 位于其中，表达透明范围、证据边界和可控守护。中文显示名为“AI Agent 守护者”，英文显示名为“AgentGuardian”。

推荐文案：

- 中文：让 AI Agent 的数据边界可见、可控、可验证。
- 英文：Local-first · Open-core · User-approved remediation.

基础色：Obsidian `#0F1215`、Cloud `#F4F6F7`、Trust `#15A36D`、Signal `#2A8CCB`、Warning `#D49A32`、Critical `#C64A43`。LOGO 同时提供 SVG、PNG、深色和浅色版本；GitHub 初代封面采用 1280 × 640，展示 Trust Frame、产品名、文案和审计概览，不放真实用户数据。

## 13. Alpha 发布门

Founder Alpha 只有在以下条件全部通过后才能标记完成：

1. 核心扫描和规则测试通过，正负样本可复现。
2. 原始敏感值不会进入普通日志、报告、智能体提示词和网络出口。
3. 修复动作必须经过批准，失败可回滚，复审能发现残留状态。
4. 自审计能显示自身权限、构建信息和网络外发状态。
5. 公开文档明确范围、限制、证据置信度和未覆盖项。
6. 独立审查智能体完成一次只读安全复核，所有严重问题有关闭证据或明确阻断发布。

若关键门失败，版本保持内部 Alpha，报告失败原因和下一步，不以“基本完成”替代验收。
